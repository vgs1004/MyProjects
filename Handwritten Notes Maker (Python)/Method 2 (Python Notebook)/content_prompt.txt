Topic: <TOPIC NAME HERE> (from zero to confident). Use the latest official docs, and W3Schools-style coverage.

Write ONE Markdown file for my "handwritten notes maker" notebook. Follow the attached notes_format_guide.md exactly. Output only the .md file content, nothing else.

Audience and depth
- Complete beginner learning alone; adult tone, no school framing.
- Plain-English explanation of every concept, many worked examples with REAL results (calculate them correctly), common traps, and a takeaway cloud on every page.
- Use one realistic business dataset throughout (show it as tables on an early page), different from a school example.
- Cover every angle, function, and variant so I have no follow-up questions. No page limit on the total file, but do not pad pages with empty space either (see density rule below). End with 2 to 3 Q&A pages using ::: qa.
- Before you finish, list every sub-topic a complete course on this subject would need (functions, keywords, concepts, settings, shortcuts, gotchas) and check each one got at least one page. If something is missing, add a page for it rather than stopping early.

Density rule (important)
- Every page must be genuinely full: combine 5 to 8 blocks per page (a box, a table, a worked example, a callout, a steps list, a takeaway) rather than 2 to 3 thin ones. A page should look like a packed notebook page, not a page with a lot of empty space.
- Only start a new "#" page when the current one is actually full. Never split a topic across pages just to keep each page short.
- Do not insert blank lines or filler text to pad a page. If a topic only needs a few lines, merge it onto the same page as a related topic instead of giving it a page of its own.
- Keep each page printable on ONE A4 page. If you expect more than about 8 blocks or a table longer than 14 rows, start a new page.

Colour rules (important, this is what makes the pages look rich)
- Every page: a short title (max 5 words, so it fits on one line), then a line `<!-- sub: one-sentence subtitle -->`.
- Group pages with `<!-- section: Part 1 · Name -->` lines; the part name appears above each title.
- Use `::: box colour "Title" :icon:` generously and vary the colours (blue, teal, red, green, purple, amber, pink) so neighbouring boxes differ. Never leave a page with only black ink and tables.
- Every code example goes in a fenced block with a language (```sql, ```dax, ```python, ```js) so keywords, functions, values and comments are coloured.
- Under every code example add `> plain: what it means in everyday words`.
- Show every result as a small table, or as ((chips)) for short lists, e.g. ((Whole Milk 1.10)). Use ((g:ok)) and ((r:error)) for good and bad outcomes.
- Use {r:red}, {g:green}, {b:blue}, {t:teal}, {p:purple}, {a:amber}, {k:pink} ink for key words, and ==highlights== for the one idea to remember.
- Use ::: parts to label the pieces of a statement, ::: chain (or ::: chain v) for process and order-of-execution diagrams, ::: flow where a node-style flow fits, and ::: grid 2 or ::: grid 3 for side-by-side comparison cards.
- Cheat sheet and practice pages: tables with a coloured box per group; practice questions as `- [ ]` checklists grouped by level, with answers on the following pages.

Format rules
- Start with front matter: title, subtitle, kicker, tagline, cover_icons, chips, footer. Put quotes around any value containing a colon.
- Every page starts with "# Title".
- Use the markers generously: ## headings, tables, ==highlights==, [[keys]], {r:coloured ink}, :icons: (only names from the guide), > tip / warning / example / pro / remember / ai / cost callouts, > takeaway, > sticky, ::: steps, ::: cols, ::: grid, ::: box, ::: parts, ::: chain, ::: flow where a process fits, - [x] checklists.
- Put formulas and inline code in `backticks`.
- Nesting: block nesting is fixed automatically, but always close every ::: block, and leave a blank line before and after every --- column separator.
- No em dashes.
